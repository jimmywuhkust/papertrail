# PaperTrail venue library (2016–2025)

Reproducible, complete-publication-year paper metadata for nine venues, built
only from public scholarly metadata APIs. Generated by
`scripts/build-venue-library.mjs`; validated by
`scripts/validate-venue-library.mjs`.

## Layout

- `index.json` — small manifest: venue catalog, per-shard URL / record count /
  byte size / venue / year / part, per-venue per-year coverage, source
  strategy, `generatedAt`, and aggregate counts (totals, dedup, exclusions).
- `shards/<venueId>/<year>.json` — lazy-loadable shards, one per venue-year.
  Years with more than 1,000 records are split into `<year>.part-N.json`.
  Venue-years with zero records still ship a shard with an empty `records`
  array.
- `references/<venueId>/<year>.json` — separate DOI citation-edge shards for
  the two large journals. Keeping 4.17 million edges out of paper shards makes
  list/search views much cheaper to load.

Notes on sources:

- DBLP's web/REST endpoints (dblp.org) sit behind an Anubis anti-bot
  JavaScript challenge for scripted clients, so the conference streams are
  harvested through DBLP's official SPARQL endpoint
  (`https://sparql.dblp.org/sparql`) using `dblp:publishedInStream` — the same
  underlying stream data, via DBLP's supported structured API. SPARQL queries
  are POSTed form-encoded because long `VALUES` clauses exceed the GET URL
  length limit.
- Nature Communications deliberately does **not** use DBLP (DBLP is not
  complete for this journal). Both journals are fetched from OpenAlex with the
  source resolved by ISSN and the display name and publisher verified before
  bulk pagination.
- IMWUT is DBLP-complete (it is the ACM publication model for UbiComp), so it
  is harvested from the DBLP `journals/imwut` stream; UbiComp-branded
  proceedings come from DBLP's legacy `conf/huc` stream (DBLP's stream key for
  the UbiComp series). Years are assigned by DBLP `yearOfPublication`.
- Conference records are enriched from OpenAlex by DOI (citation counts,
  topics, referenced OpenAlex IDs, OpenAlex ID) in batches of 50 DOIs.

## Record fields

`id` (stable: `dblp:<key>` or `oa:<W…>`), `title`, `authors` (complete ordered
list as supplied), `year`, `venueId`, `venueName`, `series` (subvenue, e.g.
`IMWUT`/`UbiComp`, else `null`), `type` (publication type/track, e.g.
`Main paper`, `Poster`, `journal-article`), `doi` (normalized lowercase, else
`null`), `url` (canonical landing URL), `sourceId` / `sourceUrl` (source record
ID/URL), `citationCount` (only when supplied, else `null`), `openAlexId`,
`topics`, `referenceIds` (referenced OpenAlex IDs), `metadataSources`,
`sourceUpdatedAt`. Missing values are `null`/empty — never invented.

## Deduplication and exclusions

- Dedup order: normalized DOI → source ID → conservative normalized
  title+year. Counts in `index.json` → `stats.dedup`. For `ubicomp`, IMWUT
  records are harvested first so they win DOI overlaps with the conf stream.
- Excluded, with counts in `stats.exclusions`: empty titles; front matter,
  tables of contents, prefaces, author/subject indexes, covers; welcome
  messages and editorials; correction/corrigendum/erratum/retraction notices;
  proceedings-volume records; non-research record types (e.g. editorships;
  OpenAlex `paratext`); records outside 2016–2025.
- Scope exclusions (documented, also counted): co-located workshop/companion
  series that DBLP files under the same stream but under a different venue
  label (e.g. `INFOCOM WKSHPS`, `SIGCOMM Posters and Demos`,
  `MobiSys Companion`, `UbiComp/ISWC Adjunct`, `SenSys-ML`) are kept out of
  the main venue collections; `Comput. Commun. Rev.` items in the SIGCOMM
  stream are excluded as a different publication. Posters/demos published
  inside the main proceedings remain, with `type` track labels.
- Conference records receive OpenAlex `referenced_works` through DOI-based
  enrichment. Journal DOI references are stored separately under
  `references/` and sourced from Crossref; this avoids inflating ordinary
  paper-list responses. Empty arrays mean the provider returned no OpenAlex
  reference IDs.

## Regeneration

Requirements: Node.js ≥ 22, network access. No package installation.

```bash
node scripts/build-venue-library.mjs            # full build (all 9 venues)
node scripts/enrich-journal-references.mjs      # Crossref DOI-edge shards
node scripts/validate-venue-library.mjs         # offline structural validation
node scripts/validate-venue-library.mjs --spot-check   # + live source spot checks
```

Useful flags: `--only=nsdi,tit` (subset), `--fresh` (ignore HTTP cache),
`--no-enrich` (skip OpenAlex DOI enrichment), and `--no-journal-refs`
(build journal metadata without OpenAlex reference IDs when its daily API
budget is exhausted; follow with the Crossref reference enricher). Raw API responses are cached
under `scripts/.venue-cache/` (disposable, not part of the dataset) so
interrupted runs resume cheaply; a machine-readable build report is written to
`scripts/.venue-cache/build-report.json` and spot-check results to
`scripts/.venue-cache/spot-check-report.json`.

Upstream metadata remains subject to each provider's terms (DBLP CC0, OpenAlex
CC0). Citation counts and topics are point-in-time snapshots; re-run the
generator to refresh.

## Spot checks

On 2026-09-18, three records per collection were checked against Crossref,
OpenAlex, or the publisher landing page: **27/27 passed**. The same run passed
6,071,627 offline schema, shard-boundary, aggregate, uniqueness, and citation
edge checks. OpenAlex's daily free request budget was exhausted during the
online re-check, so DOI samples were independently verified through Crossref
and NSDI title samples through USENIX pages; this is recorded rather than
treated as a successful OpenAlex response.
