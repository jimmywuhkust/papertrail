# Alibaba HPN: A Data Center Network for Large Language Model Training

**ACM SIGCOMM 2024** · Kun Qian, Yongqing Xi, Jiamin Cao, Jiaqi Gao, Yichi Xu, Yu Guan, Binzhang Fu, Xuemei Shi, Fangbo Zhu, Rui Miao, Chao Wang, Peng Wang, Pengcheng Zhang, Xianlong Zeng, Eddie Ruan, Zhiping Yao, Ennan Zhai, Dennis Cai

各位观众,今天给大家带来的是 SIGCOMM 2024 的论文《Alibaba HPN》——阿里云为 LLM 训练专门设计的数据中心网络。一句话概括:传统数据中心网络根本不适合大模型训练,阿里干脆重新设计了一套,一个 Pod 里塞进 15000 块 GPU。
为什么不合适?看流量模式就明白了:普通云计算是海量小流,而 LLM 训练每台主机只有少量但巨大的周期性突发流——400Gbps 级别的集合通信。ECMP 在这种模式下必然哈希极化,流量分配严重不均。
HPN 的核心设计是两层双平面架构:同一张网卡的两条 200G 通道分别接两张平面,哈希极化在物理上被消除,路径选择的搜索空间也大幅缩小。这是它的总览图。
训练还要求 GPU 同步迭代,单点故障(通常出在 ToR 交换机上)会直接拖垮整轮训练。HPN 用双 ToR 设计替换单 ToR,一台 ToR 挂了流量自动走另一台。
规模数字很惊人:双平面设计让 ToR 到汇聚层的连接数减半,汇聚交换机能撑更多段;汇聚到核心层用 15:1 的超额订阅,又释放百分之 87.5 的端口。最终一个 Pod 容纳 15000 张卡,每张卡 400Gbps 接入。这张表总结了各机制对规模的贡献。
训练实测:2300 多块 GPU 上的真实 LLM 训练,不同网络配置下的性能对比显示 HPN 设计没有短板;集合通信性能也达到了预期。
为什么值得读?这是国内云厂商把 LLM 训练网络做到这个规模并完整公开的第一篇——从流量特征到拓扑、容错、布局全链路。做大模型基础设施的同学,这篇是必读。感兴趣的话打开下方链接读原文,我们明天见。
